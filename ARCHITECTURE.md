# Architecture — Hero Survival (ENFOS-inspired, original IP)

Read this before touching code. It defines who owns what, the contracts between
subsystems, and the rules that keep eleven parallel workstreams from colliding.

Source of truth for design: `GDD_Hero_Survival_ENFOS_Inspired_v1.0.md`.

## Stack and why

| Choice | Reason |
| --- | --- |
| **Three.js r180 + TypeScript + Vite** | Requested target. WebGL2 gives PBR, MRT, instancing and float render targets — everything the visual bar needs. Vite gives sub-second HMR, which matters when the review loop iterates dozens of times. |
| **`postprocessing` (pmndrs) + `n8ao`** | Higher quality than three's built-in composer: proper HDR chain, AgX/ACES tone mapping, SMAA, and a GTAO implementation that holds up at 1080p on the target GPU. |
| **Licensed art assets, loaded as glTF** | See the asset policy below. Procedural generation stays for terrain and materials, where it earns its keep; characters and props load real models. |
| **Fixed-timestep simulation at 30 Hz, render uncapped** | Determinism for seeded QA (GDD §7) and cheap CPU with 1000+ units (§18), while the camera and VFX still run at display rate. |

**Performance target:** 60 fps at 1920×1080 with 300 active units on a GTX 970
(4 GB, Maxwell) — the machine this project is being reviewed on. Budget:
≤ 12 ms CPU, ≤ 14 ms GPU, ≤ 700 draw calls, ≤ 2.4 GB VRAM.

## Asset policy

**Superseded on 2026-08-13.** The project ran for its first phase under a
"zero third-party assets, everything procedural" rule. That was a stricter
reading of the GDD's legal note than the note requires, and it capped character
quality at what can be assembled from primitives.

What the GDD actually forbids is assets **from Blizzard or third parties without
a licence**. The rule is therefore:

| Allowed | Not allowed |
| --- | --- |
| Assets we author | Anything ripped from another game |
| Assets we buy or licence (CC0, CC-BY, marketplace) | Assets whose licence we cannot produce |
| Assets generated by AI from our own prompts | Anything recognisably derived from Warcraft or similar |
| Mixamo animations (free with an Adobe account) | Trade dress, logos, character names from existing IP |

**Every imported asset must have its licence recorded** in
`public/models/LICENSES.md` — source, licence, author, date. An asset without a
recorded licence is treated as not allowed, no exceptions.

Procedural generation is *not* being removed. It stays where it is genuinely the
better tool: terrain, ground materials, VFX. It is being dropped only for
characters, where it was producing polygon assemblies.

## Layering

```
core/      engine loop, contracts, RNG, events, pooling, spatial hash, registry
  ↑ imported by everything, imports nothing from the layers below
art/       procedural textures + material library
render/    pipeline, lighting, post-processing, camera
world/     terrain, cliffs, water, props, vegetation, map layout
units/     mesh construction, rigs, animation, unit views
vfx/       particles, spell effects, decals, damage feedback
gameplay/  combat, spawning, AI, pathing, waves, match flow
heroes/    hero definitions, abilities, infinite progression, talents
enemies/   bestiary, behaviours, bosses
economy/   gold/influence, shops, items, sabotage
ui/        HUD, shops, tooltips, health bars
audio/     synthesis, music, SFX
```

**Import rule:** a layer may import from `core`, `art`, and its own folder.
Cross-subsystem access goes through the **service locator**, never a direct
import. This is what lets subsystems be built and reviewed independently.

## The two contracts

### 1. `src/core/contracts.ts` — data shapes

Every `*Definition` type lives here. Content is data; code reads data. Nothing in
this file declares a level cap, and nothing may add one (GDD §9).

### 2. `src/core/services.ts` — runtime surfaces

Each subsystem publishes an interface and a `ServiceKey`. To use another
subsystem: `ctx.services.get(CombatKey)`. To be used: register in `init()`.

Both files are owned by the architecture lead. **Subsystem agents may append a
new key + interface, but must not change an existing signature.** If you need a
signature changed, say so in your report instead of changing it.

## Module lifecycle

```ts
export class MySubsystem implements GameModule {
  readonly id = 'mySubsystem';
  readonly order = 300;              // < 800 simulation, 800+ presentation
  init(ctx: GameContext) { /* register services, build scene content */ }
  fixedUpdate(step: number, ctx: GameContext) { /* deterministic, 30 Hz */ }
  update(dt: number, ctx: GameContext) { /* presentation, per frame */ }
  dispose() { /* release GPU resources */ }
}
```

**Order values:**

| Range | Purpose |
| --- | --- |
| 100–199 | World / terrain |
| 200–299 | Spawning, unit lifecycle |
| 300–399 | AI, movement, pathing |
| 400–499 | Combat, abilities, statuses |
| 500–599 | Waves, match flow, economy |
| 600–699 | Progression, sabotage |
| 800–849 | Unit views, VFX |
| 850–899 | Camera |
| 900+ | Render pipeline |

**Order is also service-availability order.** `init()` runs in ascending order,
so a module can only `services.get()` something registered by a *lower* order.
Asking for a later one throws `Service not registered: …` at boot. Two ways out,
both used in this codebase:

- **Lazy lookup** — resolve on first use instead of in `init()`. The HUD (870)
  does this for the render pipeline (900).
- **Injection** — the owner hands over the reference after both exist. Movement
  (300) receives combat (400) through `bind()`.

This has caused two boot failures already; check it before adding a
`services.get()` to an `init()`.

## Determinism rules

- **Never** call `Math.random()` inside `fixedUpdate`. Use `ctx.rng`, or a forked
  stream via `ctx.rng.fork('mySubsystem')`.
- Presentation-only randomness uses `visualRng` from `core/rng.ts`. It cannot
  desync the simulation because nothing in `fixedUpdate` reads it.
- Iteration order over `Map`s is insertion order in JS — that is stable, but do
  not rely on object key order anywhere.
- **`Math.sin`, `cos`, `tan`, `atan`, `atan2`, `exp`, `log`, `log2`, `pow` and
  `hypot` are banned in simulation code.** The standard does not pin them to
  the last bit, and engines disagree: Chromium and WebKit playing the same
  match drifted apart in the last bits of a velocity inside forty seconds, and
  from there they were simulating different games. Use `core/detmath.ts`, which
  builds them from exactly-specified operations (`+ − × ÷`, `Math.sqrt`,
  comparisons) and is accurate to ~1e-16. `tests/determinism.test.js` fails the
  build if one creeps back in. `Math.floor/round/abs/min/max/sqrt/imul` and the
  bit operators are exact everywhere and stay allowed.
- The ban covers `world/field.ts`, `layout.ts`, `scatter.ts` and `validate.ts`
  too: the heightfield decides walkability and line of sight, so map generation
  is part of the simulation. Mesh building in `world/terrain.ts` is not.
- **Player input never touches the simulation directly.** Every action is a
  `Command` (`gameplay/commands.ts`) booked for a tick — solo for the next tick,
  online for the tick the server's turn assigns. A click handler that calls
  `economy.buy` or `issueOrder` itself changes one machine's match and not the
  other's.
- Presentation may read `match.playerHero` / `localTeam`; the simulation never
  may. Messages meant for one player carry `heroId` or `team` on `ui:notify`.

## Two pages, one server

- The build has two entry points (`vite.config.ts` → `build.rollupOptions.input`):
  `index.html` is the marketing landing at `/`, and `play/index.html` is the
  game at `/play/`. The landing imports only `src/landing/*`, so it carries
  none of three.js and paints on a phone long before the game bundle would
  have finished downloading. The game's own HTML, canvas and boot screen live
  in `play/index.html`.
- The match server serves both from `dist/`: a request ending in `/` resolves
  to the `index.html` inside that directory, and an unknown path falls back to
  the page it belongs to. Anything under `/play` falls back to the game, so a
  reconnecting player never lands on the marketing page instead of their match.
- Any harness or QA URL that used to be `/?qa=1` is now `/play/?qa=1`.

## Online play (server-paced lockstep)

- `npm run server` starts the match server (`server/index.ts`, port `PORT` or
  8787). `npm run dev` proxies `/ws` to it; `npm run dev:lan` exposes the game
  to other machines on the network. In production the server also serves
  `dist/`, so one process hosts everything.
- The server never simulates. It runs turns of 3 ticks (100 ms), stamps every
  command it receives into the current turn and broadcasts the turn. Clients
  simulate only up to the last turn received (`Engine.setStepLimit`).
- Every 30 ticks each client sends `checksum(match)`; the server compares them.
  When they all agree on a snapshot tick it says so (`agreed`), and each client
  marks its own snapshot of that tick as common ground. When they disagree, the
  majority's state is the one kept — a tie goes to the lowest slot — and the
  odd ones out are told to `resync`: they reload, restore the last agreed
  snapshot and replay the turns after it, while the clock waits for them as it
  would for a reconnect. After `MAX_RESYNCS` (3) the match is declared
  irrecoverable (`desync`). When changing the simulation, run a two-client
  match and check the server log for `DESYNC`.
- Pausing online is the server's to grant, not the client's to take: `pause`
  stops the turn clock for everyone, shows as a `waiting` reason, lasts
  `PAUSE_SECONDS` (90) and is rationed (`PAUSES_PER_PLAYER`, 3). Only the
  player who called it can lift it early.
- A disconnect pauses the match for everyone (`waiting`). The dropped client
  reconnects with its seat token (`net/resume.ts`); the server sends the turns
  it missed (`history`, every turn is kept) and resumes the clock once it
  reports `loaded`. A reloaded page restores this browser's latest snapshot
  (saved every 10 s to IndexedDB, `net/snapshotStore.ts`) and replays only the
  turns after it; with no snapshot it replays from turn 0. Replays run with
  presentation muted (`core/playback.ts`). After
  `RECONNECT_GRACE_SECONDS` (60) the absent player forfeits; the forfeit is a
  command, so everyone ends the match on the same tick.
- Sabotage (`gameplay/sabotage.ts`) is simulation code like any other: timed
  effects on ticks, targets chosen by id order, spawns with the match RNG.
- **Snapshots** (`Engine.snapshot` / `restore`): every simulation module with
  state implements `saveState` / `loadState`. Rules: no closures in simulation
  state (delayed ability steps are data, see `onTimer` in `abilities.ts`), and
  anything that can change a future tick must be saved. Adding state to a
  module without saving it passes every solo test and desyncs a rejoined
  player — test with a snapshot, a restore and a replay compared tick by tick.
- Known limit: floating-point maths (`Math.sin`, `pow`, `hypot`…) is only
  guaranteed identical within one JS engine. Chromium ↔ Chromium is verified;
  Firefox/Safari against Chromium is not.

## Phones and tablets

- The desktop layout is the reference and does not change. Everything for touch
  lives in `src/ui/mobile.css`, imported last, and is gated on
  `(pointer: coarse)` plus a size condition. Never on the user agent.
- Two layouts, not one shrunk: a landscape phone (`max-height: 500px`) breaks
  the bottom bar apart and moves it into the corners, because the middle of a
  phone's bottom edge is where no thumb reaches; a tablet keeps the desktop bar
  and only grows its targets. Portrait is refused outright by a full-screen
  plate that asks for the device to be turned, since the game is built around a
  landscape field of view.
- Touch targets are stated in pixels, never in `rem`. The root scale bottoms
  out at 12px on a small window, so a target sized in `rem` shrinks below the
  44px a finger needs exactly where it matters most.
- Anything that scrolls uses `dvh`, never `vh`: on a phone `vh` is the
  address-bar-expanded height, so a panel measured against it is taller than
  the screen the moment that bar retracts.
- Every `:hover` rule that changes more than a colour is wrapped in
  `@media (hover: hover) and (pointer: fine)`. A tap otherwise leaves the
  element stuck in its hover state until something else is tapped.
- The canvas owns every finger that lands on it (`touch-action: none` on
  `#viewport`), and each HUD panel states its own `touch-action` too: without
  it the browser claims a drag that began on a panel as a page scroll before
  any handler runs. `#ui-root` stays `pointer-events: none` with only real
  controls opting back in, which is what lets a tap in the empty space between
  panels reach the world.
- Gestures live in `src/ui/touch.ts` and produce the same `Command`s the mouse
  does. Input may never reach the simulation any other way (see the determinism
  rules above), so a gesture that "moves the hero" is a gesture that books a
  move command.
- On a coarse pointer the renderer starts at a lower quality tier and caps the
  pixel ratio. A phone rendering at full device pixel ratio is a slideshow, and
  the options screen can still override the choice.

## Performance rules (GDD §18)

- Pool everything that spawns more than once per second: projectiles, particles,
  damage numbers, corpses. Use `core/pool.ts`.
- Enemies render through `InstancedMesh` batched by definition id. A per-unit
  `THREE.Mesh` is only acceptable for heroes and bosses.
- Broad-phase queries go through `CombatService.spatial` (a shared
  `SpatialHash`). Never write an O(n²) loop over units.
- AI runs on a budget: split units into N buckets and update one bucket per tick.
- Every `update()` must be allocation-free in steady state. Reuse vectors.

## Registering your module

Export a factory from your folder's entry file:

```ts
// src/world/index.ts
export const createTerrainModule = () => new TerrainModule();
```

Then tell the architecture lead. **Do not edit `src/main.ts` yourself** — that
file is the single point where parallel work would conflict.

## Definition of Done (GDD §21)

A subsystem is done when: it typechecks (`npm run typecheck`), it renders without
console errors under `node tools/capture.mjs`, it holds the frame budget under
`--stress 300`, its content passes `ContentService.validate()`, and a reviewer
agent has signed off against `qa/REVIEW_RUBRIC.md`.
